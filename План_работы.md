# План работы: оперативный мониторинг затопления (КосмоХакатон 2026)

Кейс: по паре снимков Sentinel-1 и Sentinel-2 на даты «до» и «пик» получить водное зеркало на обе даты и зону нового затопления. Комплекс должен работать и тогда, когда оптика закрыта облаками.

Источники: `Постановка_кейса_—_Гидрологический_мониторинг_КосмоХакатон_2026.pdf`, `Критерии_оценки_—_Гидрологический_мониторинг_КосмоХакатон_2026.pdf`, данные — [hydrowatch_amur_dataset_lite.zip](https://drive.google.com/file/d/15bwUajgK31XtiW_EiMAAfvTAaqzA6skV/view?usp=sharing).

## Что сдаём

Пять частей, все обязательны.

1. **Модуль сегментации.** На входе SAR + оптика + вспомогательные слои. На выходе бинарные маски воды на дату «до» и на дату пика по всему району.
2. **Модуль изменений.** Сравнение двух состояний. На выходе маска нового затопления и маска убыли.
3. **Сабмит.** `submission.csv` и растры `predictions/<pair_id>_flood.tif`.
4. **Сервис.** Интерактивная карта, сводный отчёт, REST API. Запрос: полигон или bbox и две даты. Ответ: маски, контуры, числа.
5. **Репозиторий, отчёт, презентация.** Код запускается по README без ручных правок. Отчёт — исследование, не пересказ постановки. Презентация 8–12 слайдов.

К защите пускают не больше 25 команд по **техническому** баллу (50 из 100). Отраслевые 50 баллов на допуск не влияют, но решают итог после защиты.

## Данные

Единица работы и оценки — пара «район интереса × событие». Растры уже сведены на сетку 10 м, EPSG:32652, сторона 3000–4500 пикселей, площадь района 900–1650 км². Пиксель = 100 м² = 0,01 га. Площадь в гектарах = число пикселей класса × 0,01.

Районы: Благовещенск, Свободный, Константиновка, Поярково, Белогорск.

| Событие | Роль |
|---|---|
| Межень, сентябрь 2018 | контроль, 3 пары. Затопления почти нет, по ним считается устойчивость к ложным срабатываниям |
| Паводок, июль 2019 | зачёт |
| Амур, июль 2021 | зачёт |
| Зея и Селемджа, август 2021 | зачёт |

В зачёте 8 пар событий. Часть ячеек матрицы «район × событие» пустая или без эталона — в сабмит идут только пары из `sample_submission.csv`.

Состав каталога:

| Каталог | Что внутри |
|---|---|
| `vectors/` | граница Амурской области, AOI, гидросеть OSM, бассейны HydroSHEDS |
| `tables/` | реестр событий, каталог сцен, пары с датами «до» и «пик» |
| `rasters/<событие>/<AOI>/` | опорные GeoTIFF |
| `reference_masks/` | эталон, только для обучения, подбора порогов и самопроверки |
| `sample_submission.csv` | полный перечень пар |

Каналы опорной выгрузки:

- **S1_pre / S1_peak** — VV, VH, VV/VH в дБ.
- **SENTINEL2_pre / SENTINEL2_peak** — B3, B4, B8, B11 и индексы NDWI, MNDWI, NDVI, AWEIsh.
- **AUX_terrain_gsw** — slope (градусы), hand (м), occurrence (%), seasonality, max_extent, builtup.
- **ERA5** — посуточный ряд, для контекста в отчёте, не для маски.

Эталон — пятиканальный uint8: `flood`, `water_pre`, `water_peak`, `permanent`, `receded`.

Определения, от которых нельзя отступать:

- **water_pre / water_peak** — открытая вода. Затопленный лес и тростник в воду не входят.
- **permanent** — постоянная вода, occurrence GSW не ниже 80 %. Из зоны затопления исключается.
- **flood** — вода есть на пике, её не было «до», и это не постоянная вода. Это целевой класс метрики.
- **receded** — вода ушла между датами. В метрику не входит, в отчёте сервиса нужна.

Эталон собран автоматически: Оцу по VV в диапазоне −22…−12 дБ, падение обратного рассеяния на пике не меньше 3 дБ, оптика (MNDWI > 0,1, NDWI > 0,15, NDVI ≤ 0,2, AWEIsh > 0), уклон ≤ 5°, HAND ≤ 25 м, без застройки, объекты меньше 25 пикселей выкинуты. Это рецепт разметки, а не готовый ответ. Площади в сабмите считаются по **своим** маскам. Копирование эталона, ручная правка масок и готовые карты наводнений по этим парам обнуляют метрику и ведут к снятию.

Опорную выгрузку используем как вход. Своя выгрузка из Google Earth Engine на инференсе не нужна: облако на проверке недоступно, а решение без интернета обязано воспроизводиться.

## Метрика

Автоматика даёт до 10 баллов из 50 технических: 7 за Score, 3 за формат сабмита (0 или 3). Score сам по себе от 0 до 1, в баллы переводится линейно между худшей и лучшей валидной командой. Поэтому валидный сабмит важнее красивой модели: невалидный получает 0 и по метрике, и по корректности.

```
Score = 0.45·Q_flood + 0.25·Q_water_peak + 0.15·Q_water_pre + 0.15·Spec_base
```

Сходимость площади по одной паре события:

```
q = max(0, 1 - |X_сабмита - X_эталона| / max(X_эталона, порог))
```

Порог в знаменателе: 50 га для затопления, 200 га для водного зеркала. Q — среднее q по 8 парам событий.

Контроль ложных тревог на 3 парах межени:

```
доля = max(0, flood_сабмита - flood_эталона) / площадь_района
Spec_base = среднее (1 - min(1, доля / 0.005))
```

Лишние 0,5 % площади района, отнесённые к затоплению сверх эталона, обнуляют вклад пары. Пропуск на межени не штрафуется этим членом, лишняя вода — штрафуется.

`submission.csv`, UTF-8, запятая:

| колонка | смысл |
|---|---|
| `pair_id` | как в шаблоне, ни одной пары не пропускать |
| `flood_ha` | новое затопление, га, до сотых |
| `water_pre_ha` | водное зеркало «до» |
| `water_peak_ha` | водное зеркало на пике |

Правила, при нарушении которых сабмит невалиден: площади ≥ 0 и не больше площади района; `flood_ha` ≤ `water_peak_ha`; нет пустых ячеек и NaN; дробная часть через точку.

Маска: `predictions/<pair_id>_flood.tif`, GeoTIFF uint8, только 0 и 1, тот же размер, CRS и аффинное преобразование, что у растра пары. Площадь по маске и число в CSV расходятся не больше чем на 2 %. Пары без оптики не должны ронять пайплайн.

## Как решать

Метрика смотрит на **площади**, не на попиксельный IoU. Выборка — 11 пар на пяти районах, эталон автоматический. Тяжёлая сегментационная сеть здесь проигрывает по трём пунктам сразу: переобучится на открытый эталон, не даст абляций, которые просят в отчёте, и раздует память.

Рабочий порядок: сначала детерминированный физический пайплайн, который уже считает свои маски и бьёт локальный Score. Потом точечные механизмы под известные ошибки каналов. Нейросеть — только если после абляций правило упирается в потолок и есть отдельно собранные сцены **других** событий. На оцениваемых парах чужие карты наводнений запрещены.

Ошибки каналов независимы, на этом и строится слияние:

| Ситуация | Кому верить |
|---|---|
| Сплошная облачность | только S1 |
| Мутная паводковая вода | S1. NDWI на ней падает до нуля и ниже |
| Тень облака | S1 |
| Ветровая рябь | S2, если сцена чистая. S1 видит рябь как сушу |
| Асфальт, бетон, ВПП | S2 (MNDWI). S1 видит гладкую сушу как воду |
| Радиотень рельефа | S2 + уклон/HAND. Низкий σ⁰ здесь не вода |
| Затопленный лес и тростник | никому для маски воды. Double-bounce даёт высокий σ⁰, в эталоне это не вода. В сервисе — отдельный диагностический слой |

Оптика не истина для радара: разрыв дат до 5 суток, уровень за это время сдвигается. Если оптика есть, она подтверждает или отклоняет пиксель, а не подменяет дату пика.

Постоянная вода и гидрология режут ложные срабатывания, из-за которых горит Spec_base:

- occurrence ≥ 80 % — permanent, из flood вычитается;
- уклон круче ~5° и высокий HAND — не затопление (HAND — подсказка, не универсальный порог 25 м: на равнине рабочий потолок ниже, в долине выше);
- пятно затопления, не связанное с гидросетью, — кандидат на удаление;
- объекты мельче 25 пикселей (0,25 га) — шум.

## Пайплайн

```
растры пары
    │
    ├─ S1: спекл-фильтр → вода по VV (порог сцены в −22…−12 дБ)
    │       + подтверждение падением VV на пике (≥ 3 дБ) для flood
    │       + отношение VH/VV против ряби и double-bounce
    │
    ├─ S2: маска пригодности (нет дыр, индексы не «облако/тень»)
    │       → вода: MNDWI, NDWI, AWEIsh > 0, NDVI ≤ 0,2
    │       если оптики нет — ветвь пропускается, не падает
    │
    ├─ слияние по таблице ошибок выше
    │
    ├─ фильтры: slope, HAND, builtup, связность с рекой, мин. размер
    │
    ├─ permanent по occurrence
    │
    ▼
water_pre, water_peak
flood    = water_peak ∧ ¬water_pre ∧ ¬permanent
receded  = water_pre  ∧ ¬water_peak ∧ ¬permanent
    │
    ├─ predictions/<pair_id>_flood.tif
    ├─ submission.csv  (площади из масок, не из эталона)
    └─ сервис: контуры + отчёт
```

Пороги живут в одном конфиге. Seed фиксируется, даже если случайности нет: так проще выполнить требование воспроизводимости.

Локальный скорер пишется в первый день и повторяет формулы выше. Эталонные площади считаются тем же кодом, что и наши, и используются только как знаменатель q. В CSV они не попадают.

## Порядок работ

### 1. Каркас и самопроверка

Скачать zip, разложить как в постановке, прочитать `sample_submission.csv` и таблицы пар.

Написать три вещи и только их:

- загрузчик пары: каналы, CRS, transform, нодата, флаги «оптика пустая / битая»;
- подсчёт гектаров по маске (пиксель × 0,01) и сверка с площадью района;
- `score.py` — Q_flood, Q_water_peak, Q_water_pre, Spec_base, общий Score по эталону.

Прогнать скорер на самих эталонных масках. Score обязан быть 1,0. Если нет — ошибка в площадях или в списке пар, дальше идти нельзя.

Заодно снять EDA для отчёта: доля воды и flood по парам, у скольких пар оптика пустая, разрыв дат S1–S2, гистограммы VV на воде и на суше. Это раздел отчёта и одновременно карта, куда алгоритм будет ошибаться.

### 2. Базовая линия, которая уже сдаётся

Один проход по всем парам шаблона:

1. медианный или Ли-фильтр по VV/VH, окно небольшое;
2. порог воды по VV внутри −22…−12 дБ, старт — Оцу по сцене;
3. оптическая вода по индексам, если канал пригоден;
4. согласие двух веток там, где оптика есть; иначе только SAR;
5. slope, HAND, builtup, вычитание permanent, удаление крошек;
6. flood и receded по формулам выше;
7. запись маски и CSV, прогон `score.py`.

Критерий готовности шага: сабмит проходит все формальные проверки (CRS, 0/1, расхождение площади < 2 %, нет NaN, пары без оптики живы) и Score заметно выше нуля. Это уже закрывает 3 балла корректности и не обнуляет метрику.

### 3. Поднять Q_flood, не раздув ложные тревоги

Q_flood весит 0,45. Менять по одному рычагу и писать строку в таблицу абляций: вариант, четыре компонента, Score.

Порядок рычагов — от дешёвых к дорогим:

1. Падение VV «до» → «пик» не меньше 3 дБ как условие именно flood, не воды вообще. Вода «до» считается своим порогом, без этого условия.
2. Отдельный порог на каждую сцену, не один на весь набор. Калибровка по гистограмме VV, диапазон тот же.
3. VH/VV: отсечь рябь (вода перестаёт быть тёмной в VV) и double-bounce (аномально яркий возврат — не открытая вода).
4. Ветвь «оптика запрещает»: асфальт и радиотень, где S2 уверенно говорит «суша», не красить в воду.
5. Ветвь «оптика молчит»: облако, тень, мутная вода — решение только по S1.
6. Связность с гидросетью и минимальный размер. Смотреть Spec_base после каждого ужесточения: межень нельзя залить.
7. Морфология контура в конце и только если она двигает площадь в нужную сторону. Записывать дельту гектаров.

HAND не фиксировать на 25 м для всех районов. Подобрать потолок отдельно для равнинных AOI и проверить, не съедает ли он реальную пойму. Это готовый абзац в раздел «границы применимости».

### 4. Разобрать эталон, а не подгоняться под него

На 2–3 парах наложить свою маску, эталон и VV. Искать места, где рецепт организаторов систематически врёт:

- мутная вода, которую оптическая ветвь эталона выкинула;
- пойма с HAND выше жёстких 25 м;
- берег и старицы, где permanent по GSW плавает между сезонами;
- межень, где Оцу на двухмодальной гистограмме с маленьким водоёмом срывается.

В отчёт идут примеры с цифрой площади, не общие слова. Подгонять порог так, чтобы пиксель в пиксель совпал с эталоном, нельзя: это та же подмена, и на защите её видно.

### 5. Сервис поверх уже посчитанных масок

Полный конвейер скачивания Sentinel не делаем. Сервис работает по подготовленным парам датасета.

Минимум, который закрывает критерии:

- REST: тело запроса — GeoJSON-полигон или bbox, `date_before`, `date_after` (или `pair_id`). Ответ — площади, доля от площади запроса, ссылки на маску и контуры.
- Контуры воды на обе даты, flood и receded: GeoJSON, CRS как у растра, атрибуты id, тип, площадь_га.
- Карта: подложка, переключаемые слои water_pre, water_peak, flood. Достаточно лёгкой страницы на тех же ручках API.
- Отчёт в JSON: водное зеркало на каждую дату в га и км², прирост и убыль в га и км², доля затопления от запрошенного полигона, разбивка затопления по покрову (builtup и классы, которые уже есть в AUX; отдельную карту покрова не качать, пока хватает выданных каналов).
- Площади в сервисе считаются тем же кодом, что и сабмит. Два калькулятора площадей — будущий рассинхрон на 2 %.

Сценарий обновления по новой сцене S1 описать в отчёте обязательно, даже если код инкремента не успеваем: что хранится (маска предыдущего состояния, permanent, AUX), что пересчитывается (только новая вода и разность), какая задержка. Реализованный инкремент даёт доп. баллы, описание без кода тоже засчитывается.

Запуск: `docker compose up` и одна команда инференса. В README — версии, структура каталогов, конфиг порогов, пик памяти, время прогона на одну пару.

### 6. Отчёт, презентация, репетиция допуска

Отчёт по оглавлению из постановки, без воды:

1. Вход, выход, формула Score.
2. EDA из шага 1.
3. Почему не один порог и не одна сеть.
4. Схема слияния и таблица «ситуация → канал».
5. Таблица абляций.
6. Инженерные механизмы и что каждый дал в гектарах и в компонентах Score.
7. Что вошло в финал.
8. Где эталон и HAND врут, что осталось, как обновлять сервис по новому пролёту S1.

Презентация: постановка, оба модуля, слияние, четыре компонента Score, живой запрос к API, ограничения. Репетиция ответов: несинхронность, мутная вода, double-bounce, почему HAND не порог, почему площади в CSV не из `reference_masks`.

## Чего не делать

- Не писать площади из эталона и не править маски руками.
- Не звать GEE, CDSE и любые карты наводнений на инференсе.
- Не ставить абсолютные пути машины.
- Не держать пороги σ⁰ и индексов числами посреди кода.
- Не обучать сеть на этих же 8 парах «в лоб»: эталон открыт, эксперт это считает подгонкой.
- Не откладывать скачивание zip и проверку, что пары без оптики открываются.
